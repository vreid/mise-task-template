# Requirements and tools

This table connects each requirement to the tools in this repository. The
requirements come from the workshop on 2026-08-26. The source document is
`requirements.pdf`. Git does not keep that file. The table replaces the company
name in the original text with "[company]".

This table does not include CodeQL. For CodeQL, read the
[SAST comparison](sast-comparison.md).

## How to read the table

- **Requirement**: the English translation. It uses Simplified Technical
  English.
- **Original**: the German text from the workshop.
- **Tools**: the tools that do the work for this requirement.
  - ⚡ **Quick win**: the tool works with the configuration in this repository.
    It gives a direct result. It does not need project-specific rules or a long
    evaluation. Examples are Clang with `-Weverything` and the strict Oxlint
    configuration.
  - 🔬 **Longer evaluation**: the tool needs project-specific rules, models, a
    policy, or a measurement before a team can trust the result.
- **Status**: "Yes" means that a task or a configuration in this repository does
  the work. "Partly" means that a known limit applies. "Decision" means that
  people must decide. A tool cannot do this work.

The [tools table](#tools) below the requirements describes each tool.

## Tools

| Tool or setting                                                   | Purpose                                                                    | Type                 |
| ----------------------------------------------------------------- | -------------------------------------------------------------------------- | -------------------- |
| Clang with `-Weverything` and a frozen warning policy             | Compiler diagnostics for C and C++                                         | ⚡ Quick win         |
| clang-tidy, including the Clang static analyzer per file          | Bug, CERT, and analyzer checks for C and C++                               | ⚡ Quick win         |
| Oxlint with type-aware rules                                      | Lint and type checks for TypeScript                                        | ⚡ Quick win         |
| Ruff with all stable rules                                        | Lint for Python, including security rules (`S`)                            | ⚡ Quick win         |
| golangci-lint with gosec, govet, and staticcheck                  | Lint for Go, including security rules                                      | ⚡ Quick win         |
| Clippy with pedantic lints and warnings as errors                 | Lint for Rust                                                              | ⚡ Quick win         |
| .NET SDK analyzers with `latest-all` and warnings as errors       | Lint and security rules for C#                                             | ⚡ Quick win         |
| ShellCheck, markdownlint, actionlint                              | Lint for shell scripts, Markdown, and GitHub Actions                       | ⚡ Quick win         |
| Oxfmt, shfmt, Ruff, gofumpt, rustfmt, dotnet format, clang-format | Code formatters                                                            | ⚡ Quick win         |
| Syft                                                              | SBOM generation (CycloneDX and SPDX)                                       | ⚡ Quick win         |
| Grype                                                             | Known vulnerabilities (CVEs) in dependencies                               | ⚡ Quick win         |
| Betterleaks                                                       | Secrets in the working tree and in the Git history                         | ⚡ Quick win         |
| Lizard                                                            | Cyclomatic complexity and function size, with limits                       | ⚡ Quick win         |
| scc                                                               | Lines of code per language, and the difference on pull requests            | ⚡ Quick win         |
| Suppression register (`task check:suppressions`)                  | Inline exceptions must name a rule and give a reason                       | ⚡ Quick win         |
| ASan, UBSan, and LeakSanitizer in the C and C++ tests             | Memory errors and leaks at run time                                        | ⚡ Quick win         |
| VS Code workspace settings                                        | Live diagnostics from the pinned tools in the editor                       | ⚡ Quick win         |
| mise, Task, lefthook, GitHub Actions, branch protection           | Command line, pre-commit hook, CI, and pull request gate                   | ⚡ Quick win         |
| Opengrep with the 41 rules in `security/rules`                    | Data flow from input to dangerous calls; each rule covers listed APIs only | 🔬 Longer evaluation |
| Opengrep with `--taint-intrafile`                                 | Data flow through helper functions in the same file                        | 🔬 Longer evaluation |
| Open Opengrep rule collections (for example GitLab, MIT)          | More API patterns; most rules are patterns, not data flow                  | 🔬 Longer evaluation |
| Clang static analyzer in CTU mode, with a taint configuration     | Data flow across C and C++ files; firmware sources and sinks               | 🔬 Longer evaluation |
| CodeChecker                                                       | Driver for the Clang static analyzer with profiles, CTU, and baselines     | 🔬 Longer evaluation |
| Grant                                                             | Dependency license policy; the legal list does not exist yet               | 🔬 Longer evaluation |
| `task check:new`                                                  | Baseline for existing projects; each project must set its policy           | 🔬 Longer evaluation |
| Dependency-Track or SecObserve                                    | Central storage, assessment, and trends of findings                        | 🔬 Longer evaluation |
